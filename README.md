# 職缺配對 Agent v2：手動收藏 → 個人化加分

## Intent

我在 104 手動收藏的職缺，應該成為 Agent 理解我偏好的訊號，讓之後的配對越來越貼近我。

## 評分邏輯

```
最終分數 = ATS 基本分（原公式，不受偏好影響） + 相似度加分（上限 10 分）
```

- **ATS 基本分**：技術 55%、年資 15%、學歷 15%、公司類型 15%
- **相似度加分**：和手動收藏的職缺比對技能重疊度（Jaccard），只取最相似的那一筆，乘上 10
- **門檻**：104 ≥ 85、LinkedIn ≥ 80；手動收藏的職缺會在每次加入後逐筆重新計算整體偏好後更新未來推薦
- **可解釋性**：每筆加分都會記下「和哪一筆收藏相似」

## 資料流程

```
Notion 手動收藏（Clipper） ──▶ clip_parser ──▶ 錨點 ─┐
                                                      ├─▶ 去重 ─▶ 評分 ─▶ 儲存
104 / LinkedIn 每日配對信 ──▶ LLM 抽取 ──▶ url_guard ─┘
                                        （URL 不在原文就丟棄）
```

## 檔案結構

| 檔案 | 職責 |
|---|---|
| `job_matcher/url_guard.py` | 防幻覺：URL 正規化、只接受原文出現過的 URL、去重 ID |
| `job_matcher/skills.py` | 技能關鍵字辭典（固定 key） |
| `job_matcher/scoring.py` | ATS 公式、門檻、相似度加分 |
| `job_matcher/clip_parser.py` | 解析 Notion 剪藏的 104 頁面 |
| `job_matcher/storage.py` | 儲存層（目前是記憶體版，之後換 Notion 或 Firestore） |
| `job_matcher/pipeline.py` | 串起整個每日流程 |

## 手動收藏的自動歸類（`notion_sync.py`）

Notion Web Clipper 剪藏時無法自動填欄位，所以由 Agent 每次執行時補上「來源＝手動收藏」。判斷規則是三個條件同時成立：

1. 「來源」是空的
2. 「ATS分數」和「配對日期」也是空的（自動配對的紀錄一定有這兩個）
3. 「JD連結」是 104 職缺網址

標成「手動收藏」的頁面，就是相似度加分的錨點。已經標好的不會重複寫入；有分數但沒有來源的異常資料不會被亂貼標籤。

## 偏好分析（`analysis.py`）

三組比較：**喜歡**（來源＝手動收藏）、**不喜歡**（勾選「不喜歡」）、**基準**（其他自動配對）。

| 分析 | 算法 | 回答的問題 |
|---|---|---|
| 技能 Lift | 組內比例 ÷ 基準比例（拉普拉斯平滑） | 哪些技能讓你特別想收藏／特別排斥？ |
| ATS 項目差異 | 兩組在技術分、年資分…的平均差 | 是 ATS 的哪一項造成落差？ |
| 公式低估 | 收藏了但 ATS < 85 | 公式漏掉了你在意的什麼？ |
| 公式高估 | 不喜歡但 ATS ≥ 85 | 公式高估了什麼？ |

**閘門**：喜歡或不喜歡任一組累積到 10 筆才產生建議；不足時只回報目前筆數。同一筆又收藏又勾不喜歡會被排除並另外回報。

洞察寫入 Notion「偏好洞察」資料庫，「你的決定」預設「待決定」，由你採納／否決／再觀察，並記下理由。

## 這一輪刻意不做（技術債）

- 舊紀錄的 ATS 拆解欄位留空：舊分數是原 Agent 算的，用新程式回推會和總分對不上，所以拆解從新資料開始累積；技能標籤則已從「職稱＋JD簡述」回填
- 7 筆舊紀錄的 JD簡述太籠統，抽不到明確技能（不硬補規則，避免過度擬合）
- 不喜歡的職缺目前只用於分析，不直接扣分（要不要做「負面相似度扣分」，等洞察累積後再決定）

- 自動調整權重（之後做成「建議 → 你確認」）
- 負面訊號（「不適合」按鈕）
- 接上真實的 Notion API 與 LLM（目前用樣本資料驗證邏輯）
- 同溫層防護的 exploration 名額

## 關於測試資料

`tests/fixtures/` 中的「真實資料」來自實際的 Notion 剪藏與配對總表，公開版已將公司名稱改為代號（例如「電信C」「範例科技」），並移除職缺編號與 Notion 頁面 ID。資料結構、標籤與勾選分布保持不變，所以測試結果與原始版本相同。
